## Questions / risks / things I noticed outside my scope
1. `denyGeo()` (helpers/geo.ts) only calls `clearPermissions()`, which in headless Chromium leaves geolocation at "prompt". The request is never answered, so the app shows "locating" until its own 15 s timeout (then "unavailable", not "denied"). In E2E-GEO-04 I therefore also set the permission to "denied" through a browser CDP session (`Browser.setPermission`) after calling `denyGeo`. Suggest the helper owner (P0-03) make `denyGeo` do this so other tests get a real denial.
2. E2E-GEO-05 visits each fixture route with a direct `page.goto` (hash navigation), with geolocation granted so that any stray call would succeed and be counted.
