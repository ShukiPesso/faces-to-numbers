2. **Deviation, `@content-data` types:** `tsconfig.json` has no `paths` entry for `@content-data`, so `tsc` failed with TS2307 on `import { raw } from '@content-data'`. I fixed it inside my owned folder with an ambient declaration in `src/content/fixtures/content-data.d.ts`. That file declares `raw: RawContentSet`, and both data modules annotate `raw` with the same type, so the three stay consistent. The location is odd. A cleaner home is `src/vite-env.d.ts` or a `paths` entry in `tsconfig.json`; the owner of those files can move it there and delete mine.
3. **How `validateContent` avoids cascades:** reference checks use the ids of *all* raw items, including items that failed zod. So a person with a schema error does not also cause "unknown person" errors at its stations. The bidirectional checks run only between items that parsed.
4. Generated JSON under `src/content/data/` is not Prettier-formatted (`prettier --check` warns on 10 files). It is F-02 output and I did not change it. It is harmless as long as `.prettierignore` or the CI format check excludes it. I did not check whether that is the case.
