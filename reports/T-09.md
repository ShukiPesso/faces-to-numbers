## Questions / risks / things I noticed outside my scope
1. **Hash-route URLs are merged by Lighthouse CI (decision taken, please confirm).** I used `?page=…` on the three URLs. Without it, the gate would apply `median-run` across nine runs as if they were one page, and the per-page gate would be lost. The alternative is one `lhci` config per page, which breaks the single-config task spec.
2. **`median-run` is not the median score (please confirm the gate).** Lighthouse CI picks the representative run by FCP/TTI, not by performance score. In run A, the station page's median score was 0.88 but `median-run` reported 0.92, and the person page's median score was 0.92 but `median-run` reported 0.95. The station page is therefore borderline in this container: a score-median gate (`aggregationMethod: "median"`) would have failed the station page in run A. Run B passed on every method. F-19 and F-20 measured this page at 88–94, so the 0.9 floor is close to the current noise. I kept `median-run` as instructed and did not change any threshold.
3. **`.lighthouseci/` should be in `.gitignore`.** It is not there yet. The directory is written by every local run and by CI, and must not be committed. That file is owned by another task.
4. **Chrome in GitHub Actions is not run here.** I verified only locally with the pinned Chromium. The workflow relies on the Chrome that `ubuntu-latest` provides, found by chrome-launcher. `--no-sandbox` is set in chromeFlags.
5. **F-20 has landed on this branch**, so these numbers already include the offline-panel and font-fallback fixes. Before F-20 the performance medians were 86–89 (`review/F-19-performance.md`), below the 0.9 floor.
