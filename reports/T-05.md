## What I did
Wrote the three `@sw` end-to-end tests against the production preview build (port 4173, started by the Playwright `webServer`). E2E-OFF-01 opens the site online, waits until the service worker controls the page (one reload only if `clientsClaim` has not taken over yet), cuts the network, then opens **every** route from `allRoutes()` (20 routes: 4 static, 7 stations, 9 people) as a brand-new document (`about:blank` → `/#<route>`) so the HTML, script, styles and fonts must come from the service worker. For each route it asserts the h1 is visible and non-empty, `<main id="main">` is not empty and the offline indicator is visible with text. E2E-OFF-02 reloads the app shell offline and then cold-opens a station deep link. E2E-PWA-01 fetches the manifest from `<link rel="manifest">`, checks every required field, checks that each icon is actually served, and checks `navigator.serviceWorker.getRegistration()`.

Missing-file reporting (task step 4): every test collects `requestfailed` URLs (ignoring `net::ERR_ABORTED`, which is a request the browser cancelled because the test navigated, not a missing file) and responses with status ≥ 400. Because Chromium can reuse a file still held in memory without asking the service worker (a deleted font went unnoticed in a first probe), each route also checks that every same-origin resource the document used (resource timing + the document itself via the `index.html` navigation fallback) is in Cache Storage. The failure message names the route and the URLs.
