## Questions / risks / things I noticed outside my scope
1. **Offline-ready banner = biggest CLS source (0.107, every first visit).** `src/components/layout/OfflineIndicator.tsx` inserts the message above `<main>` ~2 s after load. Needs a design decision (layout.md §6 places it in the banner slot) — e.g. a fixed panel above the BottomNav. Owner F-18 / design.
2. **Font swap shift** (up to 0.057): preload the three Hebrew woff2 files or add `size-adjust` fallback faces.
3. **Runtime `zod`** (54 KB min) duplicates the build-time `content:check`; skipping it in production is an Architecture §6 decision.
4. **Lighthouse noise:** same build scored 79 and 91 on the station page. T-09 / T-11 should gate on the median of ≥ 3 runs.
5. The task's verify command uses port 4173 and `--preset=perf` (performance only); I used port 4191 per the environment rules and added accessibility + best-practices so the A11y criterion is actually measured.
6. Lighthouse's `--blocked-url-patterns=*sw.js` did not stop service-worker registration in my run (scores/CLS identical), so I used a Playwright probe with `serviceWorkers: 'block'` to isolate the banner shift.
