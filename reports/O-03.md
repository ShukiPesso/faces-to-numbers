## Questions / risks / things I noticed outside my scope
1. **Key type vs. the 2026-10-15 change.** Base44 (S2) says that from 2026-10-15 *account* API keys sent in `api_key` are rejected. Workspace keys are documented in `api_key` (S1), so if the secret is a workspace key with `apps:deploy` (per DECISIONS #2), it is unaffected. If Shuki actually created a personal access token, he needs to set the repository variable `BASE44_AUTH_HEADER=bearer`. A 401 in the first run would point to this.
2. **`playwright.config.ts` always starts both webServers** (`real` and `fixture` builds and previews), even for `--project=smoke`. So the smoke job also builds the site twice locally. It works, but is slow, and a local build failure would block smoke. This is the same issue T-10 reported. I did not change it (not my file).
3. The deploy job runs `npm run check`, which includes the build, and then `npm run build` again, as the task listed. This is redundant but harmless. The E2E suite is not re-run in deploy; it runs in `ci.yml` on push to main.
4. Third-party actions are pinned to major tags (`@v4`), matching `ci.yml`. Pinning to commit SHAs would be stricter.
5. The app ID is stored as a secret, so GitHub masks it as `***` in logs (for example in the `sent to:` line). This is expected.
