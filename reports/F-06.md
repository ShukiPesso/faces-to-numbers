## Deviations / decisions (please review)
1. **Skip link click handler.** In a hash router, following `href="#main"` would navigate to the route `/main` and show NotFound. The link keeps `href="#main"` but uses `preventDefault()` and focuses `<main>` itself (tested).
2. **Focus on route change** happens only on a real change, not on first load, so the first Tab still reaches the skip link (E2E-A11Y-02). It is also skipped when the new page has already moved focus inside `<main>`. Child effects run before the parent effect, so without this check AppLayout would steal the focus F-14 sets on `where-am-i` for `/tour?locate=1`.
3. **Reserved bottom space** is padding on the frame wrapper below the Footer, not on `<main>`. layout.md §0 puts the padding on `main` but also says the Footer must never be covered. With the padding on `main`, the Footer, which comes after `main`, would sit under the fixed BottomNav. The amount is the same: `--bottomnav-size + --stickybar-size + safe-area + --space-6`.
4. **Sticky bar measurement hook for F-15.** `useReservedBottomSpace` looks for an element with `[data-sticky-bar]` after each route change. F-15 must put `data-sticky-bar` on the sticky prev/next bar. When there is none, `--stickybar-size` is set to `0px`.
5. **SideNav station list** is a simple inline `<ol>` built from `getStations()` and `getVisited()`, as F-06 step 6 says. It shows an order marker, a visually hidden `tour.stationOf`, the title, and for visited stations a `Check` icon plus a visually hidden `tour.visited`, with `aria-current="page"` on the current station. `ProgressStepper variant="compact"` (F-10) does not exist yet. F-10 or a later task may want to swap it in.
6. **Station and Person stubs** show the content `title` / `name` as the h1 and document title (no `he.ts` key fits). For an unknown slug or id they render `NotFoundPage` inline, as Architecture §4 requires.
7. **Main focus ring kept.** `<main tabindex=-1>` shows the global `:focus-visible` ring when keyboard users navigate (§5 "visible focus ring on every focusable element"). Design may prefer to suppress it on this programmatic target.
8. **Colour classes.** The Tailwind theme has no `transparent` colour, so `border-transparent` is not generated. Current-page indicators are therefore absolutely positioned spans (`border-t-accent-line` / `border-s-accent-line border-primary`).

## Questions / risks / things I noticed outside my scope
1. **Home document title repeats the name.** The home h1 is `app.name`, and §4 asks for `"<page title> · פנים למספרים"`, so the title becomes `פנים למספרים · פנים למספרים`. F-13 or D-07 should decide whether home uses `app.name` alone or `app.tagline` + suffix.
2. **Date format.** The footer shows `lastContentReview` exactly as stored (`2026-10-11`, in `<bdi>`). No date formatter is defined in Architecture §6. If a Hebrew format is wanted, it needs a lib function and a task.
3. **Component tests and RTL cleanup.** `tests/setup.ts` does not call Testing Library's `cleanup()`, because Vitest `globals` is off and auto-cleanup does not run. My test file calls `cleanup()` in its own `afterEach`. Later component-test authors will hit the same issue (P0-03 / setup owner).
4. **Shared `tsbuildinfo`.** `tsconfig.json` writes `node_modules/.tmp/tsconfig.app.tsbuildinfo`, and `node_modules` is shared by all worktrees. Parallel `tsc -b` runs could race on it. I saw no problem.
5. **Footer at lg** is centred in `--content-max` under both columns rather than aligned exactly to the reading column (layout.md §5 "content aligned to the reading column"). This is a small visual difference that D-09 or T-07 may want to adjust.
6. A single 404 appeared in the preview console on first load (no favicon is linked yet; D-08/F-18 territory).
