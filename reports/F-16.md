## Deviations / decisions
1. **Quote position for graphic people at 5 דקות.** ADR-007 puts the quote after personality/past/after. The G2 step requires the quote and altQuote inside *the same* gate as oct7. So for `graphic` people they are rendered inside the oct7 gate, directly after the oct7 text, at both m2 and m5. At m5 that moves them above "מי הוא היה". `standard` people keep the ADR-007 order unchanged. Only one gate appears per depth.
2. **Anemone end-of-story mark** (mockup `person-m5.html`, `.story-end`) is not rendered. `public/` has no `mark.svg` and I don't own an asset path. A follow-up task could add it.
3. The gate state resets when the depth changes, because the panel is keyed by depth. A gate that was opened stays opened, because `ContentWarningGate` reads `isGateOpened` from sessionStorage. A "skipped" gate shows closed again after a depth switch.

## Questions / risks / things I noticed outside my scope
1. **BLOCKER: `tests/component/layout.test.tsx:123` (owner F-06) conflicts with F-16 step 3.** The test expects the `h1` accessible name to be exactly `person.name`. F-16 requires `name + ' ' + honorific`, and every real person has `הי״ד`, so the test now fails. I did not touch the test (§2.1, §7). Suggested one-line fix by its owner or the orchestrator: `name: person.honorific ? \`${person.name} ${person.honorific}\` : person.name` (the `document.title` assertion is still correct).
2. **For Shuki (G2 intent): aviel-rahamim.** Both his `quote` ("ברגע שראיתי את הצעיף ידעתי שאחי נרצח") and his `altQuote` also appear word for word inside his `after` text, which is not gated. The quote blocks are hidden behind the gate, but the same words are visible in "מה קרה אחר כך" at 5 דקות. This is content placement, not a code issue. I changed nothing.
3. **For Shuki:** some `photo.referenceUrl` values are also listed as `sources` (for example eliyahu-harosh, lezichram.police.gov.il). They appear only as source links, never as images. This is fine under §1.3; I note it for awareness.
4. **`PersonCard` (F-12) links** use `Button href={personPath(id)}`, which gives `href="/person/<id>"`. Under hash routing (ADR-002) a real `<a href>` without `#` may leave the SPA. I have not verified this; please check it in F-15/E2E. My back link uses React Router `<Link>`, which renders `#/station/<slug>`.
5. A single 404 console error appears on the first page load in `vite preview`. It is a resource the page didn't request directly (probably favicon/manifest/SW) and is not related to this page.
