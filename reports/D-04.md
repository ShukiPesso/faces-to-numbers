## What I did
I built the 11 required mockups as self-contained HTML. Each links `../tokens.css` and inlines all of its
other CSS. A small generator (`design/mockups/_build/build.mjs`) writes every file, reading content from
`src/content/data/*.json` and UI strings from `src/i18n/he.ts`. As a result, no text about a person was typed or
paraphrased by hand. The layouts follow the D-03 component specs, the D-06 icons (Lucide shapes inlined), the
D-05 route map (inlined, with its hex colors mapped to tokens) and the D-08 anemone mark. Each page works at
base, md and lg. A small inline script only toggles states on a tap: read-aloud, depth tabs, the
content-warning gate, the silence moment and "mark visited". I took 33 Chromium screenshots and checked every
page for horizontal scroll at 320, 360, 390, 820, 1024 and 1440 px.

## Deviations
1. **UI strings come from `src/i18n/he.ts`, not `contracts/strings.he.ts`.** D-07 has since changed 18
   values in `he.ts` (the contract file says only values may change, and only by D-07). The mockups show
   the wording that will ship. For example, `silence.ended` is now "רגע השקט הסתיים…" instead of "תודה שעצרתם".
2. **Fonts are bundled** in `design/mockups/fonts/` (OFL). Otherwise the system fallback here (DejaVu or
   FreeSerif) would misrepresent the design.
3. **Screenshots** come from a Playwright script, not the `npx playwright screenshot` CLI, using Chromium only.
   They are full-page: the viewport is grown to the page height so the fixed bars render once, at the bottom.
4. **Route map** is limited to `--content-max / 2` wide at md and up. At full reading width the portrait SVG
   would be about 1,280 px tall.
5. **Footer at lg** is aligned to the reading column, per layout.md §5. F-06 currently centers it across the
   full width.
6. **Header mark** (`design/brand/mark.svg`) is shown in the header slot. F-06's Header does not render it yet.
7. **person-s30** uses roni-eshel. The task does not name a person, and the inputs list only roni-eshel and
   aner-shapira.

## Questions / risks / things I noticed outside my scope
1. **F-11 bug risk (RouteMap): RTL inheritance breaks the map labels.** Inlined into the RTL page, the SVG
   inherits `direction: rtl`, so every `<text>` label flips across its marker and "הדרך הביתה" is clipped.
   The D-05 preview did not show this because it was rendered standalone. The fix is `direction: ltr` on the
   `<svg>`, which the mockup does. F-11 must do the same.
2. **Graphic quote outside the gate (aner-shapira).** Under ADR-007 the quote is shown at m2 and m5 outside
   `ContentWarningGate`. Its text contains the detail the gate hides. This needs Shuki's decision; I did not
   change any content.
3. **Map marker states conflict.** `design/route-map.md` (D-05) uses gold for "visited" with no shape cue.
   `design/components/tour.md` §4 allows only primary, ink, ink-muted and surface, and requires a shape cue.
   The mockup follows route-map.md, which leaves "visited" on the map carried by color alone. The station
   list next to the map does say "ביקרתם כאן" in text.
4. **NearbyBanner `at` / `near` cannot occur yet.** No station location is verified. In `states.html` these
   two states use a real station title with an example distance, clearly marked as an example.
5. **No `tour.contactEmail`**, so About shows no contact line even though the about text invites corrections.
6. **P5 wording vs D-03.** `01-principles.md` P5 mentions a static "שקט" label in the running state, while
   `reading.md` §3 keeps the title and prompt and swaps only the button. The mockup follows reading.md (the
   later, more specific spec).
