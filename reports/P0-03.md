## Deviations / decisions (please confirm)
1. **`PW_CHROMIUM_PATH` override** in `playwright.config.ts`. It applies only to the Chromium projects and only when the env var is set, so CI is unaffected. It was needed locally because the installed browser builds don't match.
2. **`forbidOnly: isCI`** added to the Playwright config. It wasn't in the steps, but it enforces Conventions §7 ("no `test.only`").
3. **`allRoutes()` fallback is `['/']`**, as task step 9 says. The orchestrator note said "return just the static routes". I followed the task file. Changing it to `['/', '/tour', '/about', '/sources']` is a one-line change if preferred.
4. **`spyGeolocation(page)` returns `Promise<() => Promise<number>>`**: you call it before `goto`, then call the returned function to read `window.__geoCalls`. §3 says "→ count of `getCurrentPosition` calls" without fixing the shape.
5. **`expectTapTargets` skips every element inside `[data-inline-text]`** (task step 7). Testing Strategy §3 says "ignores links inside". These differ only for non-link controls inside inline text.
6. Test ID **`E2E-INFRA-01`** isn't in the §4 catalog. I named it so the trivial infra test has a stable ID.
7. **Coverage is configured but not on by default** (`coverage.enabled` stays false), so `npm test` doesn't enforce thresholds. `npx vitest run --coverage` does. The task didn't say to enable it by default, and enforcing `src/components/**` ≥ 80% inside `npm test` would fail feature PRs that land components before their test tasks.

## Questions / risks / things I noticed outside my scope
1. **Coverage enforcement in CI**: should the CI job (O-02) run `vitest run --coverage`? Strategy §1 says thresholds are "enforced", but the build order of F-* and T-* tasks decides when that can be turned on.
2. **`stations.json` shape assumed**: an array of objects with a string `slug`. People are read from `people/*.json`, each with a string `id`. Station routes follow file order; person routes follow sorted file name. F-02 must produce this shape, or `allRoutes()` throws a clear error.
3. **Skip link and tap targets**: if F-* builds the skip link with the common `sr-only` pattern (1×1 px but "visible" to layout), `expectTapTargets` will flag it in E2E-LAYOUT-02. The skip link should be off-screen at full size, or `display:none`/`visibility:hidden` until focused. I didn't add a heuristic for this, to avoid guessing.
4. **Smoke project starts both local web servers too**: Playwright starts every `webServer` regardless of the selected project. Running `--project=smoke` after deploy will build the app twice for nothing. Consider gating `webServer` on `!process.env.LIVE_URL` (needs approval; it isn't in the spec).
5. Builds log a Tailwind warning, "No utility classes were detected", from the placeholder app. Harmless now, and outside my scope (P0-01/F-04).
6. The `fixture` build resolves `@content-data` to `src/content/data.fixture.ts`, which doesn't exist yet. It builds today only because `main.tsx` doesn't import it.
