## Deviations
1. **The people section is left out when `personIds` is empty** (closing-drive has no people). The task says to leave out only the companions section, but rendering the heading "האנשים של המקום הזה" with nothing under it would be misleading. The sources section is left out when empty, as specified.
2. **The access section always renders**, because NavLinks / "location being checked" lives in it (as in the mockup). The notes paragraph renders only when `accessNotes` is present (it is present for all 7 stations today).
3. **Prev/next links are router `<Link>`s styled like Button `secondary`**, not the `Button` primitive. Button cannot take router links, start/end alignment, the `--space-9` min height or the two-line label from the spec.
4. **DriveBanner position:** it comes after the header block (title, subtitle, meta, share) and before the first section, as in the approved mockup. It is not between the h1 and the subtitle.
5. Screenshots are in a `reports/F-15/` folder (precedent: `reports/F-06/`).

## Questions / risks / things I noticed outside my scope
1. **Bug in PersonCard (F-10), confirmed in Chromium:** the "לסיפור של …" button uses `href={personPath(id)}`, which is `/person/aner-shapira` with no `#`. In the hash-routed app, clicking it leaves the SPA (the URL becomes `http://host/person/aner-shapira`). The jsdom tests do not catch this. NearbyBanner already does it correctly with `` `#${stationPath(...)}` ``. This needs a fix in `src/components/tour/PersonCard.tsx` (or a router `Link`). I did not touch it.
2. If the window is resized across the lg breakpoint without a route change, F-06's hook keeps observing the same bar element, so `--stickybar-size` updates through its ResizeObserver. Nothing breaks. I note it only because the bar now changes between fixed and static.
3. The design specs both `aria-pressed` and a label that switches on `mark-visited`, and this page follows it. Screen readers then announce "pressed" plus "לבטל את הסימון". That is acceptable, but worth a look in the a11y pass (T-0x).
4. The vite **dev** server cannot serve the fonts in this worktree, because `node_modules` is a symlink outside Vite's `fs.allow` (403s). I used a build plus `vite preview` for the visual check. This does not affect production.
