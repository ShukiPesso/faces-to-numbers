## Deviations / decisions (please confirm)
1. **`clientsClaim: true` (with `skipWaiting: false`).** Without it the first worker never controls the page that installed it, so the open tab would not work offline until a reload, and `tests/e2e/helpers/offline.ts → waitForServiceWorker` (requires `navigator.serviceWorker.controller !== null`) would never pass. `clientsClaim` causes no reload: a new version still waits until the visitor taps update (verified in the probe). I read the task's "no automatic skipWaiting/clientsClaim reload" as forbidding the automatic *reload*; if it means "no clientsClaim at all", remove that one line.
2. **Ready message timing.** Task step 3 says hide after 6 s; `design/components/layout.md` §6 says "stays until closed or the next route change". I implemented 6 s auto-hide **plus** the design's close button; I did not add the route-change hide (the 6 s covers it).
3. **`theme-color` meta kept `#FAF8F4`** (paper) as scaffolded, while the manifest `theme_color` is `#1F3864` per the task. Chrome prefers the meta when present, so the browser bar stays paper-coloured. Say if you want them equal.
4. `includeManifestIcons: false` so icons are not listed twice (they already match `globPatterns`). `manifest.webmanifest` is still listed twice (plugin + glob pattern from the task) — harmless, same revision.
5. Added `og:type`, `og:image:width/height`, `twitter:card`, `twitter:image` (D-08 README names `twitter:image`). og:description = `app.tagline` verbatim.
