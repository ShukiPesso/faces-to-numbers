## What I did
Wrote three Vitest integrity files under `tests/integrity/`. `drift.test.ts` (CI-03) runs `npm run content:check` via `execSync` (repo root, 60 s timeout) and fails with stdout/stderr in the message. `source-fidelity.test.ts` (CI-04) is a second, independent Markdown reader written only from `content-source/README.md`: it strips front matter, splits on `/^## .+ · (\w+)\s*$/`, and compares each section with the matching JSON field (text: whitespace-normalised equality; bullets: item-by-item, same count and order; `guideLevels` → `s30/m2/m5`; `quote`/`altQuote` → `{text, by}`). It also checks the reverse direction (no JSON field without a section, no unknown JSON field) and the front-matter strings `name`/`title`/`subtitle`. `sources.test.ts` (CI-05) parses `- <title> — <url>` (split on the LAST ` — `), compares URL sets and titles, and checks the one-to-one mapping between JSON objects (`sourceFile`) and Markdown files. Each file has negative self-checks on in-memory fictional data (§1.11), which show the comparison can fail. Nothing is written to disk.

No real mismatch was found: the committed JSON matches `content-source/` on every section checked.

## Questions / risks / things I noticed outside my scope
1. **Small deviation:** besides `name`/`title`/`subtitle`, the front-matter check also compares the person `honorific` (`הי״ד`) exactly, because visitors read it. Every file passes.
2. **Not covered by CI-04:** some visitor-visible text lives inside inline YAML in the front matter: the station `silenceMoment.prompt` (e.g. closing-drive) and `location.note`. The spec limits front-matter checks to simple keys, so this test does not check them independently. They are still covered by CI-03, which compares the converter output byte-for-byte. A future task could add an independent check if wanted.
3. The text comparison collapses whitespace, as the spec says. It would not catch a converter that drops or merges paragraph breaks (`\n\n`). CI-03 would catch it against the committed JSON, but not a bug that is present in both the converter and the committed JSON.
4. CI-05 compares source URLs as sets and titles per URL, as the spec says. It does not check that sources keep the same order. The current data is in the same order on both sides.
