# H-04 — Add family-approved photos (after launch is fine)

| Agent | Model | Wave | Size | Status |
|---|---|---|---|---|
| human | human | 7 · Post-launch | M | todo |

**Depends on:** **H-03** (Inform the families and record their consent (runs in parallel; blocks public launch)), **F-02** (Content converter — Markdown sources to validated JSON (anti-hallucination core))  
**Unblocks:** —

## Goal
Photos that families explicitly approved appear on the site with credit and alt text.

## Read-only inputs
- docs/03_CONVENTIONS.md (always)
- `review/H-03-consent-tracker.md`
- `content-source/README.md`

## Owns files — you may create or modify ONLY these
- `public/photos/`
- `content-source/people/`
- `reports/H-04.md` (your report)

## Steps
1. Only for people whose tracker row says photo permission yes: take the original file from the family, crop to portrait 4:5, export WebP ≤ 120 KB to public/photos/<person-id>.webp.
2. In that person's front matter add photo: { src: /photos/<person-id>.webp, alt: <short Hebrew description>, credit: <photographer or family> } and set consent: granted (see content-source/README.md).
3. Run npm run content:build and commit.

## Do NOT
- Never use a press or news photo. Never use a photo without written permission.

## Acceptance criteria — all must be true
- [ ] Every cleared photo has a tracker row with written permission and a file in public/photos/, and the integrity tests pass.

## How to verify
- `npm run content:check && npm test -- tests/integrity`

## Definition of Done
Conventions §10 applies. Write `reports/H-04.md` from `templates/REPORT_TEMPLATE.md`. If anything is unclear or missing: stop, set status BLOCKED in the report, and ask (Conventions §11).
