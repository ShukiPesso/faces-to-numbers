## Goal
We know from a real deploy — not from guessing — exactly how to publish the static build to Base44, how the hosting behaves, and how to fall back to another host.

## Context
Base44 documents POST /api/apps/{app_id}/deploy-dist ("Deploy a prebuilt site", BETA): upload a .tar.gz of the
build folder's CONTENTS (index.html at the archive root), at most 50 MB packed and unpacked and 1,000 files,
5 requests per minute per workspace. It replaces the whole published site and returns { deployed_at, app_url }.
It accepts a personal API key with editor access or a workspace key with the apps:deploy scope.
The API host, the authentication header name and the upload encoding (multipart field vs raw body) are NOT in
this plan. Find them in Base44's official API documentation, or ask the orchestrator to read the contract with
the Base44 MCP tool describe_api. Never guess them.

## Steps
1. Find and record (with source links) the API base URL, the auth header and the upload encoding for deploy-dist.
2. Create spike/: index.html (lang he, dir rtl, an h1, links to '#/a' and '#/b'), sw.js that precaches index.html, manifest.webmanifest, and a tiny inline script that registers sw.js.
3. Write scripts/deploy-base44.sh: set -euo pipefail; inputs DIST_DIR (default dist), BASE44_APP_ID, BASE44_API_KEY, optional BASE44_API_BASE — all from environment variables, never echoed; pack with tar -czf site.tar.gz -C "$DIST_DIR" .; refuse to upload if the archive is over 50 MB or the folder has more than 1000 files; upload with curl --fail-with-body; print deployed_at and app_url; if $GITHUB_OUTPUT is set append app_url=<url> to it; exit non-zero on any failure.
4. Deploy spike/ with the script. On the live URL record: (1) index.html status and content-type; (2) sw.js content-type and whether it registers; (3) whether '/#/b' loads; (4) what '/does-not-exist' returns (index or 404); (5) cache-control headers for index.html and for a static asset; (6) HTTPS; (7) whether a second deploy within the same minute is accepted.
5. Write docs/DEPLOY_BASE44.md: the exact request (curl example with placeholders), auth header name, encoding, limits, the seven observations with pasted curl -I output, a rollback procedure (redeploy the previous dist artifact), and a tested-on-paper fallback: deploying the same dist/ to Cloudflare Pages or Netlify in under 10 minutes.

## Do NOT
- Do not guess the host, the header or the encoding — find a source or report BLOCKED.
- Do not print, commit or paste the API key; pass it only through environment variables.
- Do not deploy more than 5 times in one minute.
- Do not use the Base44 builder AI to create or change app code.
