## Goal

## Steps
1. scripts/content/parse.ts — export: parseFrontMatter(text, file) using gray-matter (throw Error(`${file}: missing front matter`) if there is none); splitSections(body, file) → Record<string, string> following content-source/README.md rules 1–4 (heading regex /^## (.+) · ([A-Za-z0-9]+)\s*$/, lines before the first heading ignored, body trimmed, 3+ consecutive newlines collapsed to exactly 2, throw on duplicate key); parseBullets(text, file); parseGuideLevels(text, file) (exactly 3 bullets, strip the leading '**label:** '); parseQuote(text, file) (exactly the two lines '> „…”' and '> — …'); parseSources(text, file) (split each line on the LAST ' — ').
2. scripts/content/to-json.ts — export personFromMd(relPath, text), stationFromMd(relPath, text), tourFromMd(relPath, text) mapping exactly per content-source/README.md: sourceFile = relPath with forward slashes; photo = cleared object when front matter has photo AND consent is 'granted', else { status: 'pending', referenceUrl } (omit referenceUrl if absent); consent = { family: consent ?? 'not_contacted' }; every date (lastVerified, lastContentReview, verifiedAt) written as 'YYYY-MM-DD' even if YAML parsed it as a Date; optional fields omitted when absent; null only for location and silenceMoment.
3. scripts/content/build-content.ts (run by tsx) — read content-source/people/*.md, stations/*.md and tour.md; convert; validate each object with PersonSchema, StationSchema, TourSchema — on any error print the file and the zod issues and exit 1; write src/content/data/people/<id>.json (one per person), src/content/data/stations.json (array sorted by order) and src/content/data/tour.json; serialize with JSON.stringify(obj, null, 2) + '\n' after ordering keys by a fixed KEY_ORDER array per type so output is byte-stable.
4. --check flag — build in memory, compare with the files on disk, print the names of differing or missing files and exit 1 if any differ; exit 0 otherwise.
5. Run npm run content:build and commit everything it generates under src/content/data/.
6. tests/unit/parse.test.ts — UT-PARSE-01..05 using small inline FICTIONAL Markdown strings.
7. tests/unit/to-json.test.ts — UT-PARSE-06/07, plus the oracle test: read the two real source files from disk, convert them, expect(result).toEqual(JSON.parse(example file)).

## Do NOT
- Never edit content-source/ to make conversion easier — if a file does not match the documented format, stop (BLOCKED) and report the file and line.
- Never change, trim inside, normalize quotation marks in, or 'fix' Hebrew text. Only README rule 2 whitespace handling is allowed.
- Do not hand-edit anything in src/content/data/.
- Do not use a Markdown parsing library to split sections — use the line-based rules.
