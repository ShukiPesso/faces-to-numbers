**Depends on:** none — can start immediately

## Goal
All open decisions are answered and the accounts and secrets the build needs exist.

## Context
Several tasks are blocked until Shuki decides (hosting approach, name, closing stop wording, family outreach).
Deploying needs a Base44 app id and an API key that is allowed to deploy. The key is a secret: it lives only in
the repository's encrypted secrets, never in a file or a chat message.

## Read-only inputs
- docs/03_CONVENTIONS.md (always)
- `docs/07_DECISIONS_FOR_SHUKI.md`
- `docs/02_ARCHITECTURE.md`

## Owns files — you may create or modify ONLY these
- `docs/DECISIONS_ANSWERS.md`
- `reports/H-01.md` (your report)

## Steps
1. Read docs/07_DECISIONS_FOR_SHUKI.md and write one line per decision in docs/DECISIONS_ANSWERS.md (decision number, answer). Writing 'default' is a valid answer.
2. In Base44, create an empty app named 'פנים למספרים' (or ask the orchestrator to create it with the Base44 tools) and write its App ID in docs/DECISIONS_ANSWERS.md. The App ID is not secret.
3. Create a workspace API key with the apps:deploy scope only. Store it only as a repository secret.
4. Create a private GitHub repository and give the orchestrator access. The orchestrator commits this plan package as the first commit.
5. Add repository secrets BASE44_APP_ID and BASE44_API_KEY (GitHub → Settings → Secrets and variables → Actions).

## Do NOT
- Do not write the API key in any file, issue, chat or commit message.
- Do not use a key with broader permissions than apps:deploy if a scoped key is possible.

## Acceptance criteria — all must be true
- [ ] docs/DECISIONS_ANSWERS.md has an answer for each of the 16 decisions.
- [ ] The repository exists and the secrets BASE44_APP_ID and BASE44_API_KEY are listed in its settings.
- [ ] The Base44 App ID is recorded in docs/DECISIONS_ANSWERS.md.

## How to verify
- Orchestrator confirms the two secret names exist in the repository settings (values are never shown).
