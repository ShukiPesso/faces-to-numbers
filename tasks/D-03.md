| Agent | Model | Wave | Size | Status |

**Depends on:** **D-02** (Design tokens with a contrast table)

## Goal
Developers can build every component without making a single visual decision.

## Read-only inputs
- docs/03_CONVENTIONS.md (always)
- `docs/05_DESIGN_BRIEF.md`
- `design/01-principles.md`
- `design/tokens.json`
- `docs/04_TESTING_STRATEGY.md`
- `docs/02_ARCHITECTURE.md`
- `contracts/strings.he.ts`
- `contracts/example-person.json`
- `contracts/example-station.json`

## Owns files — you may create or modify ONLY these
- `design/components/`
- `reports/D-03.md` (your report)

## Steps
1. Create four files: design/components/layout.md (Header, BottomNav, SideNav, Footer, OfflineIndicator, UpdatePrompt, sticky prev/next bar), primitives.md (Button primary/secondary/quiet/link, SectionHeading, DurationBadge, QuoteBlock, PhotoFrame pending/cleared, SourceList, Markdown typography, ShareButton), tour.md (StationCard, PersonCard primary/companion, ProgressStepper, RouteMap container, NearbyBanner in all 7 states, NavLinks verified/unverified, DriveBanner), reading.md (DepthTabs, ContentWarningGate closed/opened/skipped, SilenceMoment idle/running/ended, ReadAloudToggle).
2. For each component write: purpose; anatomy as an ASCII sketch drawn RTL (start = right); the props it needs (names and types from contracts); every state; sizes at base, md and lg; the token name for every color, font, space and radius; the Lucide icon name if any; the exact string keys from contracts/strings.he.ts it shows; accessibility (element/role, aria attributes, focus order, live region); its data-testid from docs/04_TESTING_STRATEGY.md §6; and 'Don't' notes.
3. BottomNav: 4 items (בית, המסלול, איפה אני, אודות) with icon + visible label, fixed bottom with safe-area inset, shown below lg. SideNav: ordered station list + the same links, shown at lg and up.
4. Sticky prev/next bar for station pages on mobile, sitting above the BottomNav without covering content.
5. If a needed string key is missing from contracts/strings.he.ts, list it under 'Missing strings' at the end of the file — do not invent new keys in specs.

## Do NOT
- Do not use raw hex colors or px values in specs — token names only.
- Do not specify motion longer than 200 ms.
- Do not design icon-only actions.

## Acceptance criteria — all must be true
- [ ] Every component named in docs/05_DESIGN_BRIEF.md §6 has a spec with all fields from step 2.
- [ ] No raw hex color appears in design/components/*.md.
- [ ] Every component that has a data-testid in Testing Strategy §6 lists it.

## How to verify
- `grep -c '#[0-9A-Fa-f]\{6\}' design/components/*.md   (expect 0 for every file)`

## Definition of Done
Conventions §10 applies. Write `reports/D-03.md` from `templates/REPORT_TEMPLATE.md`. If anything is unclear or missing: stop, set status BLOCKED in the report, and ask (Conventions §11).
