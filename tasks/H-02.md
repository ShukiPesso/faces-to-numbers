# H-02 — Verify station coordinates and set them in the content source

| Agent | Model | Wave | Size | Status |
|---|---|---|---|---|
| human | human | 2 · Building blocks | M | todo |

**Depends on:** **C-03** (Candidate coordinates for every station (for Shuki to verify)), **F-02** (Content converter — Markdown sources to validated JSON (anti-hallucination core))  
**Unblocks:** H-06

## Goal
Every station location is either verified by Shuki and set in content-source, or stays null.

## Read-only inputs
- docs/03_CONVENTIONS.md (always)
- `review/C-03-coordinates.md`
- `content-source/README.md`

## Owns files — you may create or modify ONLY these
- `content-source/stations/`
- `src/content/data/stations.json`
- `reports/H-02.md` (your report)

## Steps
1. Open review/C-03-coordinates.md. For each row check on a satellite map, or on site, that the point is a safe and legal place to arrive and park.
2. For each verified station replace the location line in content-source/stations/NN_<id>.md exactly as shown in content-source/README.md (verified: true, verifiedBy, verifiedAt, note).
3. Leave location: null for anything you are not sure about — the app then shows 'location being verified' and no navigation buttons.
4. Run npm run content:build (or ask the orchestrator) and commit the regenerated src/content/data/stations.json.

## Do NOT
- Do not mark a point verified unless you personally checked it.

## Acceptance criteria — all must be true
- [ ] Every station has a verified location or null, and npm run content:check passes.

## How to verify
- `npm run content:build && npm run content:check`

## Definition of Done
Conventions §10 applies. Write `reports/H-02.md` from `templates/REPORT_TEMPLATE.md`. If anything is unclear or missing: stop, set status BLOCKED in the report, and ask (Conventions §11).
