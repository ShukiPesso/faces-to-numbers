# T-09 — Lighthouse CI — performance, accessibility, best practices (LH-01)

| Agent | Model | Wave | Size | Status |
|---|---|---|---|---|
| test | haiku | 5 · PWA, deploy & end-to-end tests | S | done |

**Depends on:** **F-18** (Offline PWA — manifest, service worker, offline indicator, update prompt), **F-19** (Performance pass against the budgets), **O-02** (Continuous integration — checks, bundle budgets, end-to-end on every pull request)  
**Unblocks:** L-01, T-11

## Goal
Every pull request to main is measured on a simulated mid-range phone, and drops below the budgets fail the build.

## Context
Lighthouse 12 removed the PWA category, so LH-02 (installable / offline) is covered by E2E-PWA-01 and
E2E-OFF-02 in T-05, not here. Use @lhci/cli through npx (no new dependency in package.json).

## Read-only inputs
- docs/03_CONVENTIONS.md (always)
- `docs/04_TESTING_STRATEGY.md`
- `docs/02_ARCHITECTURE.md`
- `.github/workflows/ci.yml`

## Owns files — you may create or modify ONLY these
- `lighthouserc.json`
- `.github/workflows/lighthouse.yml`
- `reports/T-09.md` (your report)

## Steps
1. lighthouserc.json: ci.collect.staticDistDir './dist'; url: index plus '#/station/<first slug>' and '#/person/<first id>' read from the real content (hard-code the three URLs in the file and add a comment line in the workflow saying where they come from); numberOfRuns 3; settings preset default mobile (do not set 'desktop').
2. ci.assert.assertions: categories:performance minScore 0.9, categories:accessibility 0.95, categories:best-practices 0.95 — all 'error'. upload.target 'temporary-public-storage' is NOT allowed (content stays private) → use 'filesystem' with outputDir '.lighthouseci'.
3. .github/workflows/lighthouse.yml: on pull_request to main; Node 20; npm ci; npm run build; npx --yes @lhci/cli@0.14 autorun; upload .lighthouseci as an artifact.

## Do NOT
- Do not upload reports to public storage. Do not add a 'pwa' category assertion (it no longer exists).

## Acceptance criteria — all must be true

## How to verify
