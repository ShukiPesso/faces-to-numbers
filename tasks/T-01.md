## Goal
Every word a visitor reads is proven to come verbatim from content-source/ — by code that shares nothing with the converter, so a bug in one is caught by the other.

## Context
This is the anti-hallucination safety net of the whole project (ADR-003). The converter (F-02) turns
content-source/*.md into src/content/data/*.json. You write a SECOND, independent reader of the same
Markdown and compare. You must NOT import anything from scripts/content/ — if you reuse the converter,
the test proves nothing. Write your own small regex code, deliberately simple.

## Steps
1. drift.test.ts (CI-03): run `npm run content:check` with child_process.execSync (cwd = repo root, timeout 60 s) and expect exit code 0. On failure include stdout/stderr in the assertion message so the reviewer sees which file drifted.
2. source-fidelity.test.ts (CI-04): for every file in content-source/people/*.md, content-source/stations/*.md and content-source/tour.md: (1) strip the front matter (text between the first two lines that are exactly '---'); (2) split the rest on lines matching /^## .+ · (\w+)\s*$/ — your own regex, written here; (3) for each section, find the matching JSON object (person by file name → id; station by file name; tour.json) and the field with the same key.
3. Comparison rules per section type (from content-source/README.md): text sections → normalize both sides (collapse all whitespace runs to one space, trim) and expect the JSON field to EQUAL the normalized Markdown body; bullet sections → each '- ' line (without '- ') equals the matching array item, same count and order; guideLevels → the three bullets with the leading '**…:** ' removed equal s30, m2, m5; quote/altQuote → text and by equal the two lines without '> „', '”', '> — '; sources → see sources.test.ts (skip here).
4. Also assert the reverse direction: every text field present in a JSON object has a section in its Markdown file (no field appears from nowhere). Fields generated by the converter (id, order, sourceFile, photo, consent, location, …) come from front matter — for those check only: front matter `name`, `title`, `subtitle` equal the JSON values exactly.
5. Name each test after the file and key, e.g. `CI-04 people/04_roni-eshel.md · oct7`, so a failure points at one section.
6. sources.test.ts (CI-05): for every Markdown file parse each line of the sources section as '- <title> — <url>' (split on the LAST ' — '); expect the set of URLs to equal the set of JSON `sources[].url` for that object, and titles to match. Then: every person JSON and station in stations.json has exactly one Markdown file whose name matches its sourceFile, and every Markdown file has exactly one JSON object.
7. Add one deliberately broken in-memory case per test file (e.g. compare against a cloned JSON with one changed word) and assert your comparison function reports it — this proves the test can fail. Do not write to disk.

## Do NOT
- Do NOT import from scripts/content/ (the converter) or from src/content/loader.ts. Reading JSON files with fs + JSON.parse is fine; importing the zod schemas is fine.
- Do not edit content-source/ or src/content/data/ to make a test pass. A real mismatch is a finding: stop and report it.

## Acceptance criteria — all must be true
- [ ] CI-03, CI-04 and CI-05 pass on the real content.
- [ ] grep shows no import of scripts/content in tests/integrity/.
- [ ] Each file contains a negative self-check that proves the comparison can fail.
