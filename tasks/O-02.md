# O-02 — Continuous integration — checks, bundle budgets, end-to-end on every pull request

**Depends on:** **P0-01** (Scaffold the repository with every dependency and npm script), **P0-03** (Test infrastructure — Vitest, Playwright projects and shared helpers)  
**Unblocks:** O-03, T-09

## Goal
No pull request reaches main unless lint, types, content drift, unit/component/integrity tests, budgets and all end-to-end projects pass.

## Read-only inputs
- docs/03_CONVENTIONS.md (always)
- `docs/02_ARCHITECTURE.md`
- `docs/04_TESTING_STRATEGY.md`
- `package.json`
- `playwright.config.ts`

## Owns files — you may create or modify ONLY these
- `.github/workflows/ci.yml`
- `scripts/check-bundle-size.mjs`
- `tests/unit/check-bundle-size.test.ts`
- `reports/O-02.md` (your report)

## Steps
1. scripts/check-bundle-size.mjs (plain Node 20 ESM, no dependencies): read dist/ recursively; gzip each .js and .css with zlib.gzipSync; sum JS gzip, CSS gzip, raw size of .woff2 files, total size of files listed in dist/sw.js precache (if sw.js is missing, use the total of dist/), and the number of files. Compare against the budgets in docs/02_ARCHITECTURE.md §9 (put them in one BUDGETS constant at the top). Print a table (budget, actual, limit, OK/FAIL). Exit 1 if any FAIL or if dist/ does not exist (with a clear message: run npm run build first).
2. Export the pure comparison function (e.g. evaluate(sizes, budgets) → rows) and test it in tests/unit/check-bundle-size.test.ts with inline numbers: all under, one over, exactly at the limit (passes).
3. .github/workflows/ci.yml — on pull_request and push to main. Job `check`: ubuntu-latest, actions/checkout@v4, actions/setup-node@v4 with node 20 and cache npm, npm ci, npm run check. Job `e2e` (needs check): npm ci, npx playwright install --with-deps chromium webkit, npx playwright test (all projects except smoke, which is skipped automatically without LIVE_URL); always upload playwright-report/ and test-results/ as artifacts (retention 14 days).
4. Set `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }` and `permissions: contents: read`.
5. Write in your report the exact branch-protection settings Shuki must turn on in GitHub (required checks: check, e2e; require PR before merge) — you cannot change repository settings yourself.

## Do NOT
- No secrets in this workflow. It must work on pull requests from branches without access to BASE44_* secrets.
- Do not add dependencies to package.json (owned by P0-01).

## Acceptance criteria — all must be true
- [ ] The bundle-size unit test passes; the script prints the table and exits 0 on a fresh `npm run build` of the scaffold.
- [ ] The workflow file is valid (actionlint or a dry run) and its steps match the npm scripts in docs/02_ARCHITECTURE.md §7.

## How to verify
- `npx vitest run tests/unit/check-bundle-size.test.ts`
- `npm run build && node scripts/check-bundle-size.mjs`
- `npx --yes actionlint-bin@1 .github/workflows/ci.yml || echo 'actionlint unavailable — check YAML by eye and say so in the report'`

## Definition of Done
Conventions §10 applies. Write `reports/O-02.md` from `templates/REPORT_TEMPLATE.md`. If anything is unclear or missing: stop, set status BLOCKED in the report, and ask (Conventions §11).
