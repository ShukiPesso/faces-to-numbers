# O-03 — Deploy pipeline to Base44 with post-deploy smoke tests

| Agent | Model | Wave | Size | Status |
|---|---|---|---|---|
| devops | opus | 5 · PWA, deploy & end-to-end tests | M | review |

**Depends on:** **O-01** (Spike — verify Base44 deploy-dist end to end and document it), **O-02** (Continuous integration — checks, bundle budgets, end-to-end on every pull request), **F-18** (Offline PWA — manifest, service worker, offline indicator, update prompt), **T-10** (Post-deploy smoke tests against the live URL (E2E-SMOKE-01..03))  
**Unblocks:** C-04, H-05, L-01

## Goal
A merge to main publishes the tested build to Base44 automatically, then proves the live site works — and a bad deploy can be rolled back in minutes.

## Context
O-01 already proved the deploy-dist call by hand and documented the exact host, auth header and encoding in
docs/DEPLOY_BASE44.md. Use exactly that — do not guess or "improve" the API call. The API key is a secret:
it exists only as the GitHub repository secret BASE44_API_KEY (Shuki adds it). It must never appear in a
file, a log line, a commit, a report or chat. BASE44_APP_ID is also stored as a secret.

## Steps
1. Harden scripts/deploy-base44.sh from O-01: keep set -euo pipefail; refuse to run if dist/index.html is missing; check the 50 MB / 1000 files limits before upload; on HTTP 429 wait 65 s and retry once (5 requests/minute limit); never print the request headers; print only deployed_at and app_url.
2. .github/workflows/deploy.yml — on push to main and workflow_dispatch. `concurrency: { group: deploy, cancel-in-progress: false }`. Job `deploy`: environment `production`; npm ci; npm run check; npm run build; upload dist/ as artifact `site-<short sha>` (retention 90 days — this is the rollback copy); run scripts/deploy-base44.sh with env BASE44_APP_ID and BASE44_API_KEY from secrets; expose app_url as a job output.
3. Job `smoke` (needs deploy): npm ci; npx playwright install --with-deps chromium; LIVE_URL=${{ needs.deploy.outputs.app_url }} npx playwright test --project=smoke. Upload the report.
4. Add a workflow_dispatch input `rollback_run_id`: when given, download the artifact from that run instead of building, and deploy it (same script). Document the exact click-path in docs/DEPLOY_BASE44.md.
5. Update docs/DEPLOY_BASE44.md: one-time setup for Shuki (create the two secrets, create the `production` environment with himself as required reviewer), how a deploy runs, how to roll back, how to move to another static host if the beta API changes (R-01): the dist/ folder works on any static host because routing is hash-based.
6. First real deploy: run the workflow via workflow_dispatch, attach the run URL and the live URL to your report.

## Do NOT
- Never write, echo or commit the API key. Never use `set -x` in the deploy script. Never use the Base44 builder AI to change the app.
- Do not deploy from pull requests or from branches other than main.

## Acceptance criteria — all must be true
- [ ] One successful run: deploy job green, smoke job green against the real Base44 URL.
- [ ] `git grep -n BASE44_API_KEY` shows only references to the secret name, never a value.
- [ ] docs/DEPLOY_BASE44.md has setup, deploy, rollback and host-migration sections.

## How to verify
- `bash -n scripts/deploy-base44.sh`
- `git grep -nE "(api[_-]?key|token)\s*[:=]\s*['\"][A-Za-z0-9]{12,}" || echo 'no hard-coded secrets'`
- `LIVE_URL=<app_url from the run> npx playwright test --project=smoke`
